UNIVERSITY OF TRENTO · ENT-LAB · JUN–SEP 2026

60 GHz radar gesture recognition on MSP430

Embedded signal processing and four-class TinyCNN inference on a resource-constrained microcontroller.

02

System pipeline

Infineon BGT60LTR11AIP radar I/Q → 2 kHz ADC → first-difference clutter removal → Q15 Hann window and 256-point FFT using TI DSPLib/LEA → 256 × 15 spectrogram → integer TinyCNN → UART result.

Validation and measurements

85.83% integer validation accuracy on 240 held-out validation tensors; 2,620 model parameters, approximately 5.3 kB integer model. A documented live run produced 60 results in 120 seconds with zero reported CRC errors or resynchronizations.

Verification and limitations

I checked acquisition counters and CRCs, and confirmed exact agreement for all four logits between Python integer reference and host C on 240/240 validation samples. Recordings involved one subject, and the reserved test set remains unopened. Live output rate is not a measure of classification accuracy.

MSP430FR5994 · Embedded C · Python · Q15 STFT · LEA · TinyCNN · UART

Additional verification and model details

255 validated raw capture records across 10 sessions; training/validation/reserved-test tensors: 720/240/240. TinyCNN uses 8/16 convolution channels and 83,968 nominal MACs. Board memory usage: 3,684 of 4,096 bytes general RAM.

CS350 · THREE-PERSON TEAM · NOV 2025–JAN 2026

STM32 secure boot framework

Signed firmware updates with encrypted download, dual-slot management, rollback and recovery.

03

Architecture

For this three-person course project, we created Python tooling to version, sign and encrypt firmware packages. ECDSA-P256 authenticates the signer, SHA-256 verifies integrity and AES-128-CBC encrypts update payloads.

Implementation & verification

The bootloader design uses active, download and scratch slots so an invalid update does not necessarily destroy the last working image. We tested cryptographic vectors, MPU write protection and boot flows on STM32F746G/STM32F411.

STM32F7/F4 · Embedded C · Python · ECDSA · AES · MPU

TEI · EMBEDDED SOFTWARE INTERNSHIP · JUL–AUG 2025

STM32 incident recorder using an MPU6050 IMU

An event-triggered logger designed to preserve motion data from before and after a button press.

Objective

Record a 2.5-second interval around an event: one second of previous IMU readings and 1.5 seconds following a user-button interrupt. Each stored sample includes processed motion information and an RTC timestamp.

What I built

On an STM32 NUCLEO-G071RB, I used TIM3 to schedule MPU6050 readings over I²C every 10 ms. A 100-record circular RAM buffer continuously retained the most recent second. When the button was pressed, the firmware transferred these 100 records and collected 150 post-event records for Flash storage.

Verification and limitation

I inspected Flash contents in STM32CubeIDE to confirm the 250 eight-byte records (2,000 bytes). Writing records during capture added substantial overhead: the intended 2.5-second acquisition lasted about seven seconds in the prototype. Batch-writing after acquisition was identified as a next improvement, rather than claiming real-time recording had been achieved.

STM32G071RB · Embedded C · STM32 HAL · I²C · TIM3 · RTC · Circular Buffer · Flash

SAVRONIK · EMBEDDED SOFTWARE INTERNSHIP · JUN–JUL 2025

Bidirectional USB–UART bridge and serial monitor

Variable-length serial communication between a USB endpoint and a PC through an NXP FRDM-KL25Z.

Objective

Forward data in both directions without requiring fixed-size messages or blocking the receiving interface.

What I built

I implemented the bridge firmware in C with USB callbacks, interrupt-driven UART reception and circular FIFO buffering. I also developed a Windows Forms serial-monitor application in C# to open COM ports, send messages and inspect incoming data.

Verification

I exercised USB-to-UART and UART-to-USB transfers using the custom monitor, Hercules and virtual serial ports. The internship report documents successful bidirectional operation at 115200 baud. These were functional communication tests, not a quantified long-duration reliability benchmark.

NXP FRDM-KL25Z · Embedded C · MCUXpresso · USB CDC · UART · Interrupts · C# / WinForms

BAYKON · MANUFACTURING INTERNSHIP · JUL–AUG 2024

Continuous UART reception on STM32 with DMA

Receiving and decoding variable-length weight readings from an industrial weighing indicator.

Objective

Read repeated weight transmissions without blocking the STM32 processor and interpret the received measurement for a simple threshold-controlled output.

What I built

I configured USART reception with DMA and receiver-timeout handling on a NUCLEO-G071RB, using STM32 low-level peripherals and interrupt flags to separate incoming frames. I wrote a Python serial-port tool to generate messages during development, then parsed the indicator fields into a readable weight value.

Verification

I compared the indicator reading with the Python serial output and debugger values. In the final hardware demonstration, the system reacted to live readings by turning on an LED when the measured weight was within the selected range (1.330–1.340 kg).

STM32G071RB · Embedded C · STM32 LL · USART · DMA · Receiver Timeout · Python
